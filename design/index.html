Perch

Design review

Seven static mockups, no build step. Open any file directly in a browser. perch.css holds the whole visual language and perch.js holds the keyboard layer, so the views agree with each other.

Every screen has a working ⌘K palette and live j k navigation. Click the line reading “everything stays on this Mac” at the bottom of the rail to flip between light and dark.

The views

Feed feed.html

Reverse-chronological matched roles. Age is the only hierarchy: fresh reads warm and full-strength, a role open 200 days reads tired. Each row names the rule that fired. No scores, no badges. Toggle the empty state from the hint bar.

Detail pane detail.html

Opens beside the feed; the queue narrows rather than disappearing. Description, observed board history, hiring velocity with its caveat, and exactly two actions.

Applications applications.html

Three groups, not a table. A rejection gets the same calm row as everything else. Silence past thirty days archives itself, and the screen says so once.

Watchlist watchlist.html

Watched companies with detected ATS, including the case where there is no board API and Perch reads the careers page instead. Monitor broadly, fill narrowly. Stated in words, never a badge.

Profile profile.html

Fields backed by a human-editable profile.toml, document variants, and the model section. “No model at all” is presented as a complete way to use Perch, and pointing at a remote endpoint asks for consent at the point of use.

Application flow apply.html

Three steps: review fields → attach documents → open in webview. Filled fields carry provenance, unknowable fields stay visibly blank, and the cover letter is conspicuously empty by design. The flow ends at “Open in browser”. There is no submit primitive.

Résumé import review import.html

A diff. Every proposed field shows the source span it anchors to. One field fails verification and is not offered. Nothing reaches the profile without an explicit accept.
What the design commits to
One queue, one pane No dashboard, no home screen, no widgets. The feed is the app; everything else is a different queue in the same shape.
Time, not score Perch does not score a match. It reports how old a posting is, in plain language.
One accent Terracotta, at most three times per screen. Warm means recent. Everything else is four steps of warm grey on paper.
Keyboard first j k ↵ x and a palette whose vocabulary is the CLI's vocabulary, verbatim.
Nothing flinches Empty states, rejections, archived applications, and unsupported boards all get the same ordinary treatment. This is a tool someone opens on a bad Tuesday.
No submit The fill layer has no submit primitive. The UI cannot offer a button the program does not have.
