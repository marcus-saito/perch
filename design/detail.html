Val Town

Systems Engineer, Runtime

Remote (US) or Brooklyn · posted 2 days ago · Ashby
What they wrote

Val Town runs JavaScript that strangers write in a browser and expect to be live a second later. The team that owns that path is four people. You would be the fifth.

Today a val runs in a Deno process behind a pool of warm workers. It works, and it is expensive in both directions: we hold memory open for people who may never come back, and a cold start in a region we have not pre-warmed still costs most of a second. We are moving execution onto isolates we control, written in Rust, so that a val can start in single-digit milliseconds and be billed for the milliseconds it actually used.

That work is mostly unglamorous. A snapshot format. A scheduler with an opinion about which code is likely to be called next. Syscall filtering strict enough that calling it a sandbox is honest. And a real answer for the handful of npm packages that reach for things a sandbox will not hand them.

We are not asking that you have built a runtime before. We are asking that you are comfortable reading someone else's runtime source at two in the morning and coming away with an opinion about it.

What we are looking for:

  • Rust in production, or C++ or Go and a real willingness to write Rust daily
  • Some prior contact with V8, Deno, Bun, Wasm, or a container runtime
  • Comfort down at the operating system — seccomp, cgroups, namespaces, page cache behaviour
  • A preference for reading source over reading documentation
